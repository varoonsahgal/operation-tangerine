🚀 Deploy (Lab 1.1)

Run everything from the repo root unless a step says otherwise.

# 1. Get the code (use your fork / the repo your instructor shared)
git clone https://github.com/<you>/operation-tangerine.git
cd operation-tangerine

# 2. Configure
cd terraform
cp terraform.tfvars.example terraform.tfvars
#    edit terraform.tfvars: region, student_id (unique per person in a shared account)

# 3. Deploy (~12-15 min, Aurora is the slow part)
terraform init
terraform apply

# 4. Back to the repo root. Install labctl's only dependency and make a handy alias
cd ..
python3 -m pip install --user boto3    # "externally-managed-environment"? use a venv:
                                        #   python3 -m venv .venv && . .venv/bin/activate && pip install boto3
alias labctl="python3 $(pwd)/labctl/labctl.py"     # add to ~/.zshrc or ~/.bashrc to keep it
eval "$(labctl env)"                                 # exports $CLUSTER_ARN, $LAMBDA_NAME, $MEMORY_TABLE, ...

# 5. Seed the database (5k customers, 200k products, 100k orders)  ← Lab 1.2
labctl db-setup

# 6. Mission status: every check should be ✔ except knowledge_base (that's Day 2)
labctl status
While Aurora deploys… Day 1's IAM module is timed to run during the first terraform apply. Start the deploy, then start learning.

🕹️ labctl cheat sheet

CommandWhat it does
labctl statusResources, Data API state, and the agent's own health probe.
labctl db-setup [schema seed kb kb-rebuild indexes playground]Runs files in sql/ through the Data API. Safe to re-run. kb-rebuild drops and recreates the vector table.
labctl invoke <action> '{json}'Calls the Zest Lambda, e.g. labctl invoke search_products '{"query":"drone"}'.
labctl sql "SELECT …"One-off SQL via the Data API.
labctl embed-notesEmbeds 30 support notes with Titan V2 into support_notes.
labctl kb-sync [--full]Starts a Knowledge Base ingestion job and waits for it. --full forces every doc to re-ingest.
labctl drills · break <d> · check <d> · hint <d>Break-fix drills. check exits non-zero until the fix is right.
labctl exam start | answer q1 "…" | checkThe 140-minute mock exam lab (Day 4).
labctl mcp-json [--client vscode]Prints a working MCP config. It's a spoiler for Labs 3.4 and 3.5!

🔄 The reset button

Broke something and can't find it? Run what matches how far you've got. It won't skip ahead and solve later labs for you:

(cd terraform && terraform apply)       # always: IAM policies, Lambda env vars, Data API
labctl db-setup schema seed             # always: tables and seed data
labctl db-setup kb-rebuild              # after Lab 2.5: recreate the vector table + bedrock_user
labctl kb-sync --full                   # after Lab 2.6: refill the Knowledge Base
labctl db-setup indexes                 # after Lab 3.6: the product-search indexes

Day 4 has its own pre-exam reset that runs all of these.

Drills change things outside Terraform on purpose (that's drift). terraform plan is a fault detector: it lists exactly what was changed. On the real exam you won't have Terraform, so practice finding faults by hand first.

🩺 Setup troubleshooting

SymptomFix
build_layer.sh: python3 not found / No matching distributionMake sure python3 -m pip works and you're online. Or set enable_claude_agent = false: everything except ask still works.
