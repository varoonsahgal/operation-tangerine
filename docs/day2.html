🐘 Module 1 · Aurora PostgreSQL & the Data API

Cluster

One distributed storage volume (6 copies across 3 AZs) shared by all instances. Most settings and the Data API live here.

Instances

Compute that attaches to the volume: one writer, up to 15 readers. Ours is one db.serverless writer.

Serverless v2

Capacity in ACUs (~2 GiB RAM + CPU each), scaling in 0.5-ACU steps between your min and max. Min 0 = auto-pause.

Endpoints

Cluster (writer) endpoint, reader endpoint, and per-instance endpoints, all for TCP drivers. The Data API is separate.

Cluster ARN vs instance ARN: know the difference

arn:aws:rds:us-east-1:111122223333:cluster:tangerine-student1-aurora          ← CLUSTER (Data API, Bedrock KB, MCP server)
arn:aws:rds:us-east-1:111122223333:db:tangerine-student1-aurora-writer        ← INSTANCE (metrics, reboot, Performance Insights)
Exam lens Anything that talks SQL over the Data API takes the cluster ARN: Bedrock KB's "Aurora DB cluster ARN", the Aurora MCP server's --resource_arn, your Lambda's env var. An instance ARN in one of those fields is a classic planted fault.

The RDS Data API

  • SQL over HTTPS: ExecuteStatement, BatchExecuteStatement, BeginTransaction / CommitTransaction / RollbackTransaction.
  • Auth is IAM (rds-data:*) plus a Secrets Manager secret holding the DB user's credentials.
  • Typed, named parameters (:name + stringValue, longValue, …) keep you safe from SQL injection.
  • One statement per call. Synchronous calls stop waiting after 45 s (continueAfterTimeout lets the statement keep running).
  • Must be enabled on the cluster. For Aurora Serverless v2 and provisioned clusters, use aws rds enable-http-endpoint --resource-arn <cluster-arn> (the older modify-db-cluster --enable-http-endpoint was for Serverless v1).

The 5-point "agent access" checklist

  1. ☐ Data API enabled on the cluster.
  2. ☐ Agent role has rds-data:ExecuteStatement on the cluster ARN.
  3. ☐ Agent role has secretsmanager:GetSecretValue on the secret (plus kms:Decrypt if it uses a customer-managed key).
  4. ☐ Agent config names the right cluster ARN, secret ARN and database.
  5. ☐ The DB user in the secret exists and has GRANTs on the tables the agent queries.
Memorize this list. Objective 1 ("Configure Aurora PostgreSQL for agent access") is some combination of these five boxes, broken.

🧭 Module 3 · Embeddings & vector math

An embedding model turns text into a list of numbers (a vector) so that texts with similar meaning land close together. "My drone battery dies fast" and "Turbo Drone only flies 4 minutes" share few words but end up near each other.

Titan Text Embeddings V2

amazon.titan-embed-text-v2:0. Output 1024 dims by default (or 512 / 256). Optional normalization.

Dimensions must match

A vector(1024) column only accepts 1024-length vectors. Change models, change the column.

pgvector

The extension is named vector: CREATE EXTENSION vector; (not "pgvector"). Types: vector, halfvec, sparsevec.

Similarity search

ORDER BY embedding <=> :query_vec LIMIT k: the k nearest neighbours.

OperatorDistanceIndex opclassUse when
<->Euclidean (L2)vector_l2_opsMagnitude matters
<=>Cosine distance (1 − cos θ)vector_cosine_opsText embeddings (most common; Bedrock KB)
<#>Negative inner productvector_ip_opsNormalized vectors, fastest
<+>Manhattan (L1)vector_l1_opsRare

pgvector Fruit Playground

⏱ 25 min🍊 Easy🍋 Fun

🎯 Build intuition with 3-dimensional "flavor vectors" [sweet, sour, bitter] that you can check by eye.

  1. Create and query the playground (sql/05_pgvector_playground.sql): 
    labctl db-setup playground
    Which fruit is closest to a tangerine by L2? By cosine? Do they agree? (Skip the tangerine row itself at distance 0.)
  2. Which fruit is most like a lemon? 
    labctl sql "SELECT fruit, round((flavor <=> (SELECT flavor FROM fruit_vectors WHERE fruit='lemon'))::numeric, 3) AS dist FROM fruit_vectors WHERE fruit <> 'lemon' ORDER BY dist LIMIT 3"
  3. Cosine ignores magnitude, L2 doesn't. Predict both answers, then run: 
    labctl sql "SELECT '[1,2,3]'::vector <=> '[2,4,6]'::vector AS cosine, '[1,2,3]'::vector <-> '[2,4,6]'::vector AS l2"
  4. Break it on purpose: insert a 2-dimensional durian into a 3-dimensional column. 
    labctl sql "INSERT INTO fruit_vectors VALUES ('durian', '[0.5, 0.5]')"
What you should see
Orange is closest to tangerine by both metrics; mango is next by cosine. Step 3: cosine = 0 (same direction), L2 ≈ 3.74. Step 4 fails with expected 3 dimensions, not 2. Bedrock prints the same kind of error when a KB table is vector(1536) and Titan V2 sends 1024.
You can explain why cosine distance is the usual choice for text embeddings.

⚡ Module 4 · pgvector indexes: HNSW vs IVFFlat

Without an index, a similarity query computes the distance to every row: exact, but O(n). Approximate nearest-neighbour (ANN) indexes trade a little recall for a lot of speed.

HNSWIVFFlat
StructureMulti-layer proximity graphk-means clusters ("lists")
BuildSlower, more memory; can be built on an empty tableFaster; needs data first (to train the lists)
Query speed / recallExcellentGood; depends on probes
Build knobsm (16), ef_construction (64)lists (≈ rows/1000)
Query knobSET hnsw.ef_search = 40SET ivfflat.probes = 1
Bedrock KB guidanceHNSW with vector_cosine_ops on the embedding column
Why isn't my vector index used?
  • Operator ≠ opclass: index built with vector_l2_ops, query uses <=> → sequential scan.
  • No ORDER BY distance LIMIT k → the planner can't use the ANN index.
  • Tiny table → the planner correctly decides a seq scan is cheaper.
  • Heavy WHERE filters + ANN can return fewer than k rows; pgvector 0.8+ adds iterative scans (hnsw.iterative_scan).
LAB 2.4

Semantic Support Notes

⏱ 30 min🍊🍊 Medium

🎯 Give Zest semantic memory of past tickets with real Titan embeddings, then watch an HNSW index change a query plan.

  1. Embed 30 historical support notes into support_notes.embedding vector(1024): 
    labctl embed-notes
  2. Ask in plain language. The notes share almost no words with your query: 
    labctl invoke similar_notes '{"query":"my quadcopter only flies for a few minutes","k":3}'
labctl invoke similar_notes '{"query":"I see two payments on my card for one order","k":3}'
  3. Build a 20,000-row benchmark table of random 64-dimensional vectors: 
    labctl sql "CREATE TABLE IF NOT EXISTS vec_bench (id int PRIMARY KEY, embedding vector(64))"
labctl sql "INSERT INTO vec_bench SELECT g, ARRAY(SELECT random() FROM generate_series(1,64) WHERE g > 0)::vector(64) FROM generate_series(1,20000) g ON CONFLICT DO NOTHING"
  4. Exact search: note the plan and the execution time: 
    labctl sql "EXPLAIN ANALYZE SELECT id FROM vec_bench ORDER BY embedding <-> (SELECT embedding FROM vec_bench WHERE id = 1) LIMIT 5"
  5. Add an HNSW index for L2 and re-run step 4: 
    labctl sql "CREATE INDEX IF NOT EXISTS vec_bench_hnsw_l2 ON vec_bench USING hnsw (embedding vector_l2_ops)"
  6. Now query with cosine instead. Is the index used? Fix it with a second index. 
    labctl sql "EXPLAIN ANALYZE SELECT id FROM vec_bench ORDER BY embedding <=> (SELECT embedding FROM vec_bench WHERE id = 1) LIMIT 5"
Solution
Step 4: Seq Scan on vec_bench + sort. Step 5: Index Scan using vec_bench_hnsw_l2, usually far faster. Step 6: back to a seq scan, because the opclass doesn't match the operator. Fix: CREATE INDEX vec_bench_hnsw_cos ON vec_bench USING hnsw (embedding vector_cosine_ops);. Clean up when done: labctl sql "DROP TABLE vec_bench".
similar_notes finds the drone-battery and double-charge notes, and you've seen Seq Scan → Index Scan in a plan.

LAB 2.7

Metadata Filters & Hybrid Search

⏱ 20 min🍊🍊 Medium

🎯 Narrow retrieval with metadata, and see where keyword matching beats pure semantics.

  1. Retrieve with a metadata filter (only product guides): 
    aws bedrock-agent-runtime retrieve --knowledge-base-id "$KNOWLEDGE_BASE_ID" \
  --retrieval-query text="My drone keeps drifting to one side" \
  --retrieval-configuration '{"vectorSearchConfiguration":{"numberOfResults":3,"filter":{"equals":{"key":"category","value":"guide"}}}}' \
  --query 'retrievalResults[].{score:score,src:location.s3Location.uri}'
  2. Same through the agent: labctl invoke search_docs '{"query":"drone drifting","category":"guide"}'
  3. Exact codes are hard for embeddings. Compare SEMANTIC and HYBRID for the ticket code BILLING-DUP: 
    for t in SEMANTIC HYBRID; do echo "== $t"; aws bedrock-agent-runtime retrieve --knowledge-base-id "$KNOWLEDGE_BASE_ID" \
  --retrieval-query text="BILLING-DUP" \
  --retrieval-configuration "{\"vectorSearchConfiguration\":{\"numberOfResults\":2,\"overrideSearchType\":\"$t\"}}" \
  --query 'retrievalResults[].location.s3Location.uri'; done
  4. Which index made hybrid search possible? Find it in pg_indexes.
Hybrid search mixes vector similarity with full-text matching (the GIN to_tsvector index on chunks). If your region or KB reports it unsupported, note that and move on. It's a bonus, not an exam objective.

BREAK-FIX 2.8

Break-Fix: The Vault Collapses

⏱ 30 min🍊🍊🍊 Hard💥 2 faults

🎯 A migration "upgraded" the vector table and a security review "tightened" the KB role. Now syncs fail. Make the Knowledge Base sync COMPLETE again.

  1. Inject both faults: 
    labctl break vector-dims
labctl break kb-role
  2. Probe: labctl kb-sync --full. --full touches every doc so Bedrock really writes to the table; a plain sync would skip unchanged docs and hide the faults. Read every failureReasons line and the row count at the end.
  3. Inspect the table (columns, types, indexes, grants). What changed?
  4. Inspect the KB service role's kb-access policy. What's missing?
  5. Fix both, re-sync with labctl kb-sync --full, then grade: 
    labctl check vector-dims && labctl check kb-role && labctl check kb-synced
Hint
Fixing one fault makes the next error message appear. If the sync error changes, you're making progress.
Solution

Fault 1: the table was recreated with vector(1536), no indexes and no grants for bedrock_user. The table is empty, so you can fix it in place. Run these in the Query Editor, or one labctl sql "…" per statement (the Data API runs one statement per call):

ALTER TABLE bedrock_integration.bedrock_kb ALTER COLUMN embedding TYPE vector(1024);
CREATE INDEX ON bedrock_integration.bedrock_kb USING hnsw (embedding vector_cosine_ops) WITH (ef_construction = 256);
CREATE INDEX ON bedrock_integration.bedrock_kb USING gin (to_tsvector('simple', chunks));
CREATE INDEX ON bedrock_integration.bedrock_kb USING gin (custom_metadata);
GRANT SELECT, INSERT, UPDATE, DELETE ON bedrock_integration.bedrock_kb TO bedrock_user;

Fault 2: the KbSecret statement was removed. Add back secretsmanager:GetSecretValue on the bedrock_user secret ARN (IAM → Roles → KB role → kb-access → Edit).

The trap: sync is incremental. The docs in S3 haven't changed, so a plain sync can finish COMPLETE while the recreated table stays empty. Force a full re-ingest by changing the docs (that's what labctl kb-sync --full does), or delete and re-create the data source. Then check that SELECT count(*) FROM bedrock_integration.bedrock_kb is above zero.

All three checks show 🏆, the table has rows again, and search_docs answers.

❓ Day 2 quiz

The Bedrock KB console asks for an "Aurora DB cluster ARN". Which value is correct?

The Data API and Bedrock KB work at the cluster level, so they need the :cluster: ARN.

Which statement enables pgvector?

The project is pgvector; the extension is named vector.

A KB uses Titan Text Embeddings V2 (default settings) and its table has embedding vector(1536). What happens on sync?

The column dimension must equal the embedding model's output dimension.

You built USING hnsw (embedding vector_l2_ops) but your query orders by embedding <=> :q. Result?

The operator (<=> = cosine) must match the opclass (vector_cosine_ops).

A KB sync fails with an access error on Secrets Manager. Which principal is missing GetSecretValue?

During sync, Bedrock calls the Data API as the KB service role, so that role must read the bedrock_user secret.

How do you enable the Data API on an Aurora Serverless v2 cluster from the CLI?

enable-http-endpoint is the API for Serverless v2 and provisioned clusters.
