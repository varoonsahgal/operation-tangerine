🧠 The 12 rules of the exam lab

📖

1. Read everything first

Spend the first ~10 minutes reading all the challenge guidance. The exam itself says most "broken" moments are a missed configuration step.

🗒️

2. Build an ARN scratchpad

Cluster ARN, secret ARNs, table name, role names, KB ID. Copy them once and paste from there. No hand-typing.

⏱️

3. Time-box

7 challenges in 140 min ≈ 17 min each + buffer. Stuck for 5 minutes? Move on and come back.

🔎

4. Probe before you poke

Reproduce with the smallest call (Lambda test event, one SQL statement, one get-item) before changing anything.

📜

5. Errors are gifts

AccessDenied names the principal, action and resource. ResourceNotFound names the thing. Read the whole message.

1️⃣

6. One change at a time

Change, re-probe, confirm. Five changes at once means you don't know which one fixed it, or which one broke something else.

🧅

7. Expect layers

Fixing a fault often reveals the next one behind it. A new error message means progress.

🔐

8. Least privilege still counts

Add the specific action on the specific resource. "*" might pass a test, but it's the wrong answer.

⚙️

9. Config before code

Wrong env var, ARN, region, database, table or KB ID: check config before suspecting the code.

🐘

10. The DB has its own rules

IAM OK + secret OK can still fail inside PostgreSQL: missing role, GRANT, extension, index or wrong vector dims.

🖱️

11. Fastest tool wins

Console for one-off edits (env vars, Data API toggle), CLI or Query Editor for SQL and checks. Mind the --environment replace trap.

✅

12. Verify like a grader

The grader checks end state, not effort. After each fix, confirm the exact success condition in the guidance.

🔍 Debrief: open after the clock stops

Challenge 1: Aurora access (2 faults)
  • Data API disabled → aws rds enable-http-endpoint --resource-arn "$CLUSTER_ARN" (or Modify cluster → RDS Data API).
  • Lambda DB_SECRET_ARN → bedrock_user secret → point it back at the admin secret.

Common mistake: granting the role access to the bedrock_user secret. IAM would pass, but bedrock_user can't read products.

Challenge 2: pgvector store (1 fault, 3 symptoms)

The table was recreated as vector(1536) with no indexes and no grants. Fix it in place (the table is empty). Run each statement separately, in the Query Editor or as one labctl sql "…" each:

ALTER TABLE bedrock_integration.bedrock_kb ALTER COLUMN embedding TYPE vector(1024);
CREATE INDEX ON bedrock_integration.bedrock_kb USING hnsw (embedding vector_cosine_ops) WITH (ef_construction = 256);
CREATE INDEX ON bedrock_integration.bedrock_kb USING gin (to_tsvector('simple', chunks));
CREATE INDEX ON bedrock_integration.bedrock_kb USING gin (custom_metadata);
GRANT SELECT, INSERT, UPDATE, DELETE ON bedrock_integration.bedrock_kb TO bedrock_user;
Challenge 3: DynamoDB memory (2 faults)
  • MEMORY_TABLE had a -v2 suffix → the real table name.
  • AgentMemory statement reduced to GetItem → restore PutItem, Query, UpdateItem, DeleteItem, BatchWriteItem on the table and /index/*.
Challenge 4: Knowledge Base (2 faults + re-sync)
  • KbSecret statement removed from the KB role → add secretsmanager:GetSecretValue on the bedrock_user secret.
  • Lambda KB_ID emptied → set it to your KB's ID.
  • After Challenge 2, force a full re-ingest. The table was dropped, but the S3 docs didn't change, so a plain incremental sync writes nothing. Change the docs (labctl kb-sync --full) or delete and re-create the data source.

Common mistakes: forgetting to sync at all, and trusting a plain sync's COMPLETE. The grader checks the latest job and that the table has rows.

Challenge 5: Aurora MCP server

--resource_arn was the writer instance ARN → cluster ARN. --database postgres → agentdb. --region and AWS_REGION → your lab region.

Investigation SQL your assistant should run:

SELECT c.segment, round(sum(o.amount)) AS total
FROM orders o JOIN customers c ON c.customer_id = o.customer_id
GROUP BY c.segment ORDER BY total DESC LIMIT 1;
Challenge 6: DynamoDB MCP server

AWS_REGION pointed at the wrong region. Fix it, then read session_id = sess-escalation-042, sk = STATE → escalation_ticket. Watch out for the decoy session sess-escalation-024!

Challenge 7: Product search
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX idx_products_name_trgm ON products USING gin (name gin_trgm_ops);
CREATE INDEX idx_products_category_rating ON products (category, rating DESC, product_id);
ANALYZE products;

⚡ Lightning round

You fixed the KB role and the recreated vector table, ran a sync, and it says COMPLETE, yet search_docs returns nothing. Why?

Bedrock still believes the docs are indexed. Change the docs (or recreate the data source) to force a full re-ingest.

Two Lambda env vars are wrong. Fastest safe fix?

Each CLI call with a one-var map would wipe the others.

A challenge says "least privilege". The agent needs Query on a GSI. Which resource do you add?

Scope it to that table's indexes.

CREATE INDEX … USING gin (name gin_trgm_ops) fails: operator class "gin_trgm_ops" does not exist. Fix?

The opclass ships with the pg_trgm extension.

Twenty minutes left and two challenges untouched. Best move?

One fully verified challenge beats two half-done ones.
